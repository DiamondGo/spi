# sPi 0.3.0

## 新功能 / What's new

### 设备列表 / Device list

- 设置 → 远程访问显示“待配对”“已配对，未连接”“已连接”，以及在线设备的“控制端 / 只读端”。
- 生成配对码后可以关闭设置，稍后回来点“查看配对码”继续复制同一个码；无需确认或保存。配对成功后设备自动保存。
- 当前同时支持一个待配对项，可取消。配对码仍只在本次 sPi 运行中有效：默认 1 小时，最长 60 天；取消、关闭远程访问或退出/重启后失效。
- Remote settings retain a pending invitation across Settings close/reopen, with View pairing code and Cancel actions. Paired devices are saved automatically and listed as connected or disconnected. One in-memory pending invitation at a time; restarting invalidates it.

### 单远程控制端 / One remote controller

- 同一时间只有一个远程连接可以控制 host，其余为只读；同一设备的多个连接也不能同时拥有控制权。本机窗口不受限制。
- 先连接者获得控制权；它断开或被撤销后，最早仍在线的只读端自动接替。重连不会抢占已有控制端。
- 只读端可以浏览 host 已打开会话的历史和实时聊天/工具输出，不能新建会话、发送消息、操作终端、修改模型/YOLO、回应审批或删除历史。当前不镜像其他设备的 PTY 画面。
- host 逐次校验权限，写入类 RPC/单向消息被阻止，不只是禁用界面按钮。已开始的操作不因控制权交接而回滚。
- Exactly one remote connection controls the host. Other connections use a passive read-only session viewer. FIFO takeover on controller disconnect/revocation; reconnects never steal control. Read-only access is enforced by a fail-closed host RPC allowlist. Local windows are unaffected.

**兼容性：远程协议升级到 v2，host 和 client 必须一起升级到 0.3.0。不与 0.2.x/v1 静默兼容。** 已保存的配对仍保留；升级本身不要求重新配对。

**Compatibility: remote protocol v2 requires both host and client to update to 0.3.0. Published 0.2.x/v1 peers are refused rather than silently bypassing role enforcement. Existing saved pairings are retained.**

### 用户提问跳转 / Navigate your questions

- 消息区右下角、滚动条内侧新增浮动上/下箭头，仅在对应方向存在视野外用户提问时显示。上按钮固定在下按钮上方。
- 点击定位到该方向最近的用户提问，只滚动消息区，不移动输入框。浏览历史时新输出不会把页面拉回底部；“回到最新”恢复跟随。
- 支持流式输出、展开/折叠工具输出、窗口缩放、切换会话、三种主题和远程只读窗口。
- Floating Previous/Next question arrows jump to the nearest offscreen user input, retain fixed upper/lower slots and update after layout changes. Browsing history pauses auto-follow; Return to latest restores it.

### 启动与钥匙串 / Startup and Keychain

- 未启用远程访问时，本地启动和被动状态徽标不再读取系统钥匙串，避免 Mac 后台等待授权造成界面启动阻塞。进入远程设置或恢复已启用的远程 host 时才检查密钥保护；远程身份仍必须由系统凭据存储加密，不提供明文回退。
- Local startup and passive status badges do not probe the OS keyring when remote hosting is disabled. Credential protection is checked explicitly in Remote settings or when resuming enabled hosting. Remote identity encryption remains mandatory; this is not a plaintext fallback.

## 平台与安装 / Platforms and installation

- Linux x64 / arm64: canonical Pi/npm installer targets.
- macOS Apple Silicon / Intel: public supplemental manual ZIPs — [Apple Silicon](https://github.com/DiamondGo/spi/releases/download/v0.3.0/spi-0.3.0-darwin-arm64.zip) · [Intel](https://github.com/DiamondGo/spi/releases/download/v0.3.0/spi-0.3.0-darwin-x64.zip) · [Mac checksums](https://github.com/DiamondGo/spi/releases/download/v0.3.0/SHA256SUMS-macos.txt). Both native builds and installed-ZIP acceptance passed. **Ad-hoc signed; NOT Developer ID signed or notarized.** Do not disable OS protections. The Linux installer manifest is not rewritten to promote automatic Mac installation.
- [Release downloads](https://github.com/DiamondGo/spi/releases/tag/v0.3.0). Existing releases and npm versions remain unchanged.

After npm publication:

```bash
pi install npm:spi-agent-gui@0.3.0
```

Existing desktop installations can use `spi update`. Save important drafts and fully quit old windows before reopening; binaries do not hot-update running windows. Pi authentication, saved pairings and sessions are preserved.
