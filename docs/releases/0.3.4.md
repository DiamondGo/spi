# sPi 0.3.4 — reliable session recovery feedback

## Changes / 更新

- **Fix stale “Pi has exited” banners after successful recovery.** Recovery RPC replies now carry the same owner health/history snapshot as the event. The renderer reconciles the result if the success event was missed; Check connection also consumes its response instead of relying on one-way notification alone.
- Order health snapshots with a monotonic owner revision. Duplicate/older recovery replies cannot rewind new output, stop a later task, or erase a newer exit state. A live, writable current owner replays its verified health on task start and already-requested state reads, even when its own status was already healthy. No additional polling, model requests, automatic queue resume or prompt replay is added. Retired/dead writers cannot revive sessions.
- **Replace native recovery `window.confirm` with a visible in-window modal**, shared by the banner and session context menu. Cancel is focused by default; Cancel/Escape send no recovery request. Only explicit Confirm recovery restarts Pi. Busy status and retryable errors are visible rather than silently returning to the old banner.
- Handle GitHub anonymous REST API 403/429 during update checks through the same repository's official `releases/latest/download/release-manifest.json` endpoint. The fallback accepts only a strictly validated stable version/manifest and still checks the exact-version descriptor and archive checksum. It adds no credentials, mirrors or trust bypass; other errors/invalid API metadata remain errors.
- Keep the existing saved-history, draft/image/outbox preservation, paused queue, YOLO reset and host-enforced read-only protections. Missing session files remain an explicit error, never a silent new conversation.

恢复成功后应自动清除退出提示及恢复按钮。确认界面不再依赖可能阻塞／不可见的原生确认框；错误会留在窗口内，可查看并重试。测试覆盖真实点击、取消/Escape、失败重试、健康事件缺失及旧回复迟到，不通过强行隐藏横幅或再次重启用户会话解决状态同步问题。

## Platforms and upgrade / 平台与升级

- Linux x64/arm64 and macOS Apple Silicon/Intel. Mac is ad-hoc signed, **not Developer ID signed or notarized**; no OS protection bypass is provided.
- Existing 0.3.3 installations can test the intended in-app path: **Settings → Check for updates**, download 0.3.4, save unsent drafts/queue contents, then explicitly confirm **Restart to apply**. `spi update` is the CLI alternative. This publication will not restart the current window for you. Installation alone does not hot-update a running app; drafts/outbox are memory-only until separately saved.
- GitHub is the primary desktop update channel; no npm action is needed for that in-app update. A matching lightweight npm package remains the first-install path: `pi install npm:spi-agent-gui@0.3.4` after public npm verification.
- Remote protocol stays v2; saved pairings/profile/history are preserved. Update host/client together to exercise all new recovery behavior. Immutable 0.3.3 assets are not replaced.

Only that exact advisory/range on lockfile-marked development nodes is allowed. Production paths, other high/critical findings and incomplete audit data still fail. Installer inputs and every final ASAR/unpacked/resources script/standalone helper must reject the affected build modules/code and provide content-hash/version-bound inventories. Upgrade/remove the exception when the official patch is available. These native-job inventories are not independent publisher signatures.
